## 1. What Meroa is

Meroa is a relationship-first AI companion. Users chat with it in natural language; it
creates and updates tasks and goals from the conversation and tracks progress over time.
Four tabs: **Chat**, **Tasks**, **Goals** (formerly "Tools"), and **You** (settings).

## 2. AI data flow (Apple Guideline 5.1.2(i))

- Chat replies are generated by a **third-party AI service: OpenAI** (`api.openai.com`),
  model **gpt-5-mini**. Utility/safety passes (crisis detection, output claim-checking) run
  on OpenAI **gpt-5-nano**. (Provider is configurable via `AI_PROVIDER`; **OpenAI** is the
  current production provider — confirm Railway `AI_PROVIDER=openai` before submit.)
- **Data flow:** when a user sends a message, the message **content** — plus server-computed
  context about the user's own tasks and goals (titles, counts) needed to reply — is sent
  over **encrypted HTTPS** to the AI service, which returns a completion. **No phone number
  and no user identifier are sent to the AI service.**
- **Explicit consent is obtained in-app before any message is sent to the AI service**, and
  the server refuses to contact the AI provider until consent is recorded (enforced
  server-side, not just in the UI). Consent is **revocable** in **You → AI data sharing**;
  revoking it stops chat from functioning until re-granted.
- The consent screen appears after sign-in/onboarding and before the user can reach Chat.

## 3. Reporting offensive AI content (Google AI-Generated Content policy)

Users can report an AI response as offensive from within the chat: open the options on an
assistant message → **Report this response** → optional reason. Reports are stored server-
side for review. No additional third-party processing occurs on a report.

## 4. Account deletion & data export

- **In-app deletion:** You tab → **Delete account** (two-step confirm). Performs an
  **immediate hard delete** of all the user's data, and **revokes the Apple Sign-in token**
  server-side (Guideline 5.1.1(v)).
- **Data export:** You tab → **Export my data**.
- Deleting the Meroa account does **not** cancel the store subscription; the app tells users
  to cancel in the App Store to stop billing.
- ⚠ **Web deletion path** is a **Google Play** requirement, not Apple. Needed only when
  submitting to Google; no dependency for the iOS submission. (Auth is now Sign in with
  Apple, so any web-deletion flow must key off Apple identity, not the old phone/SMS code.)

## 5. Reviewer access — Sign in with Apple

Sign-in uses **Sign in with Apple only** (the old phone/SMS OTP flow was removed). The
reviewer taps **"Sign in with Apple"** on the welcome screen and authenticates with their
**own Apple ID** — no demo credentials, no SMS to receive, no review bypass to wire.

**Reaching Premium features:** Meroa is a hard paywall with a 7-day free trial. The reviewer
signs the **sandbox tester** in under **Settings → Developer → Sandbox Apple Account** and
starts the trial from the paywall — full access follows immediately. (RevenueCat + App Store
Connect sandbox is configured; product `meroa_monthly`, entitlement `plus`, offering
`default`.) **Restore Purchases** is available on the paywall and in the You tab.

**Once in:** Chat is the first tab. Type *"remind me to call the dentist tomorrow at 3pm"*
to see task creation; *"I want to save $300 for a new bike"* to see goal creation; the
**Tasks** and **Goals** tabs show the same records. **You** holds settings, AI-consent
control, export, and account deletion.

## 6. Permissions & notifications

Meroa requests permissions **only at point of use**:

- **Notifications** — requested when the user enables a reminder, timer, or check-in. The app
  schedules **local** notifications **and** registers an **Expo push token** (stored
  server-side, keyed to the user) so the server can send reminder / re-engagement pushes.
  Push delivery is user-controllable (quiet hours, proactive-message limits, opt-out).
  ⚠ Because a push token **is** collected, ensure `docs/app-privacy-answers.md` /
  `docs/data-inventory.md` list it as a collected identifier before submitting the App
  Privacy questionnaire.
- No location, contacts, camera, microphone, or photo access is requested (no such features
  exist).

## 7. Data collection summary (for the privacy questionnaires)

See `docs/data-inventory.md` for the full, code-verified inventory and the field-by-field
mapping to the Apple App Privacy and Google Data Safety categories. Headlines: Apple user
identifier + optional phone (identity), message content (shared with the AI provider:
OpenAI), user-created content (tasks/goals/memories), subscription status (RevenueCat),
push token (identifier, for notifications), crash diagnostics (Sentry). No analytics SDK,
no tracking, no data sold.
